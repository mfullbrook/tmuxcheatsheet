# CEO Plan: Config-Aware tmuxlab

## Vision

### 10x Check
The site doesn't just display your config — it's where your config lives. Paste `.tmux.conf` once: the cheat sheet, search, command pages, explain tool, and (later) the playground all speak your keys. A diff view — and, later, shareable setup permalinks — make your configuration a first-class, explainable object. No tmux resource has ever been personal; this one is.

### Platform Note
The parser is infrastructure, not a feature: permalinks, diff view, playground rebinding, and a future community config gallery all build on the same parse → normalize → overlay pipeline shipping in the base plan (design doc steps 0–6).

## Scope Decisions

| 6 | Playground drill mode (timed trainer) | M | DEFERRED | Missions already teach keys at launch; trainer has own mini-launch potential ("tmux typing test") later |

Lower-priority backlog (not individually reviewed): i18n subdirectories (the incumbent's real moat), community config gallery.

## Accepted Scope (added as build step 7)

**Launch gating:** none of the three blocks launch. **Cut rule:** anything not done by the day design-doc steps 0–6 complete is cut from the launch and moves to TODOS.md. Total addition ≈ 1.5 human days / ~1.5 hrs Claude Code (the OG-image bullet is most of it); if the budget overruns, cut order is print → diff → OG.

**Sequencing:** this is a parallel track interleaved with the base plan, not an appended step. OG images are parser-independent (buildable anytime; 5 `opengraph-image.tsx` files sharing one card template + embedded font — the /config/explain card necessarily lands with design step 5 when that page exists). Print personalization needs ConfigContext (after step 4); the diff view needs parser output (after step 5).

- **Dynamic OG images** (`opengraph-image.tsx`) for /commands/[slug], /guides/[slug], /tutorial/[slug], /config/explain, and home (the cheat sheet) — keybinding/title rendered in the site's terminal aesthetic. Criteria: every listed route emits a valid 1200×630 card; command pages show the actual keybinding.
- **Print stylesheet** for the cheat sheet: same rows and state as on screen (toggle state, strike-throughs, "Your other bindings"), restyled for paper — chrome/status bar hidden, light compact two-column layout; personalized when ConfigContext is active. Criteria: prints legibly to ≤2 pages in Chrome and Safari, with and without a config applied, no interactive chrome in output. Low risk (not zero — collapsed containers and browser print variance need a QA pass).
- **Diff view** on /config/explain: table of remapped bindings (yours vs default), unbound defaults, and **options your config sets** (both classes, with values — no defaults-value table exists, so "set" not "changed vs default" is the contract) — with counts ("12 remapped · 3 unbound · 5 options set"). Criteria: correct counts for all 10 fixtures.

**Launch sequence note:** the base doc's ordering stands — deploy v1 to Vercel (unlaunched) *early* (its Next Step 2), keep deploying as steps land, r/tmux only after steps 0–6 + surviving fixtures. This plan changes nothing about that ordering.
